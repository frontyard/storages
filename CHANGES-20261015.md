# Changes

## simplefs

### Bug fixes

- `recoverEnoughSpaceIfNeeded` deleted `cache.Delete(string(item.Value()))` — a
  file path is never a cache key, so nothing was evicted and the recursion could
  overflow the stack when `directory_size` was exceeded. Replaced by `freeSpace`,
  which selects victims from the least to the most recently used item
  (`RangeBackwards`) and deletes them after the iteration.
- `Delete` inside `Range`/`RangeBackwards` callbacks could corrupt the iterated
  list (`DeleteMany`, `freeSpace`). Keys are now collected during the iteration
  and deleted after it returns.
- The `OnEviction` callback checked `item.Value()` for `MappingKeyPrefix`
  instead of `item.Key()`. Prefix sniffing is gone entirely: file-backed entries
  are tracked in a `files` map, so inline entries (mapping/surrogate keys) never
  reach the file-removal path.
- `SetMultiLevel` returned `nil` when `os.WriteFile` failed, silently dropping
  the error. It is now returned.
- The `negativeNow` duration hack for the mapping key TTL was replaced with
  `ttlcache.NoTTL`.
- Stored entries now use `duration + stale` as TTL (was `duration` only). A file
  entry expiring at `duration` could never serve its stale window, since the
  mapping advertised `duration + stale` but the entry was already gone. Matches
  the badger provider behavior.
- `Get` tried `os.ReadFile` on every non-surrogate value, including inline ones
  stored by `Set` (a doomed syscall per hit), and returned the raw file path on
  read error — garbage fed into `readResponse`. File-backed entries are now
  identified via the `files` map; a missing file returns `nil`.
- Removed `strings.Trim(value, ",")` on the stored path, which could corrupt
  paths of keys containing leading/trailing commas.
- Overwrite race: writing a file before `cache.Set` on an existing key could
  have its file removed by an eviction of the previous entry. Filenames now
  carry a unique `-seq` suffix and the eviction callback only removes a file
  when the evicted path still matches the tracked one.
- Orphaned files (e.g. after a restart, when the in-memory index is empty) were
  counted toward `actualSize` but never served nor evicted. `Init` now deletes
  every file not tracked by the index.
- `defer func() { go cache.Start() }()` replaced by a plain `go cache.Start()`.

### Behavior changes

- `directory_size` now actually limits on-disk usage: payload sizes are tracked
  per key at write time (no `os.Stat`), and `freeSpace` evicts oldest
  file-backed entries until `actualSize + needed <= directory_size`. Expired
  entries are reaped first (`cache.DeleteExpired`). A single payload larger
  than the budget is rejected with an error.
- New `disable_compression` option (bool or string, e.g. `disable_compression
  true` in a Caddyfile): values are written to disk uncompressed. Because
  `core.MappingElection` unconditionally decompresses whatever `Get` returns,
  `GetMultiLevel` uses a local election routine (`mappingElection`, mirroring
  `core.electMapping` over exported helpers) plus `readStoredResponse`, which
  reads LZ4 frames only when the `04 22 4D 18` frame magic is present. With
  compression enabled, `GetMultiLevel` still delegates to
  `core.MappingElection`, so the default path is unchanged.
- `Reset` now stops the ttlcache janitor (guarded by `sync.Once`) and explicitly
  removes all tracked files even if `Init` was never called.
- `Init` is idempotent (`sync.Once`).

### Performance

- `provider.mu` no longer wraps the read path: `Get`, `GetMultiLevel`,
  `ListKeys`, `MapKeys` and `Delete` don't serialize on it (ttlcache is
  internally synchronized). `mu` is now an `RWMutex` held only for O(1)
  bookkeeping in the `files` map / `actualSize` counter.
- No `os.Stat` calls anywhere; `OnInsertion` callback removed.
- No `provider.mu` critical section ever calls a cache method, and no cache
  callback calls back into the cache, so no lock-ordering deadlock is possible.

### Logging

- Removed the `Warnf` on every cache miss, `Debugf` on every mapping miss, and
  the per-file `Debugf` lines in `Init`.
- `os.Stat`/`os.Remove` error logs tied to eviction races were removed;
  `ReadFile` failure is logged at `Debugf` (legitimately races with eviction).
  Genuine failures stay at `Errorf`.

## Tests

- `simplefs_test.go`: all instances now use `t.TempDir()` as the storage path,
  so tests no longer write cache files into the repository (this is what
  produced the `large_value_test` artifact, now deleted).
- New tests: `TestSimplefs_SetMultiLevel_DisabledCompression`,
  `TestSimplefs_GetMultiLevel_DisabledCompression`,
  `TestSimplefs_DirectorySize_EvictsOldest`,
  `TestSimplefs_DirectorySize_TooSmall`,
  `TestSimplefs_Init_RemovesOrphanedFiles`.

## Misc

- `simplefs/caddy/Caddyfile`: example configuration now shows `directory_size`
  and `disable_compression`.

## Notes on ttlcache v3 semantics (verified against v3.3.0 source)

- Eviction/insertion callbacks run on a separate goroutine; file removal and
  `actualSize` updates are therefore asynchronous.
- The LRU list is front=most-recent, back=least-recent; `Range` iterates
  newest->oldest, `RangeBackwards` oldest->newest. Capacity eviction removes
  `lru.Back()` (the oldest).
- `Set` on an existing key updates in place and does not fire an eviction
  event.
